## Issues Found & Fixed

### ISSUE-001 — Add Card Modal Always Shows "Front cannot be empty"

- **Severity:** High
- **Category:** Functional
- **Status:** ✅ **Verified fixed**
- **Commit:** `3533c6e`

**Description:** The Add Card modal always showed "Front cannot be empty" validation error, even when text was typed. Root cause: `index.html` contains a hidden static form (`#cardFormView.hidden`) with `id="cardFrontInput"` on line 444. The modal is dynamically generated by `app.js` and creates another element with the same `id`. `document.getElementById("cardFrontInput")` in `handleAddCard()` always returned the hidden static element (DOM order precedence), not the visible modal element.

**Root Cause:** Duplicate `id` attributes in the DOM. `document.getElementById()` returns the first match in DOM order — the hidden static element.

**Fix applied:** Changed `handleAddCard()` in `js/app.js` to scope `querySelector()` to the `#addCardForm` element:
```javascript
const form = document.getElementById("addCardForm");
const frontInput = form ? form.querySelector("#cardFrontInput") : document.getElementById("cardFrontInput");
const backInput = form ? form.querySelector("#cardBackInput") : document.getElementById("cardBackInput");
```

**Evidence:**
- Before: "Front cannot be empty" error on every Add Card attempt
- After: Card successfully added; deck shows incremented card count ✅

**Screenshots:**
- `screenshots/add_card_modal.png` — Modal open with text visible but validation failing (before)
- `screenshots/issue001_after.png` — Deck showing 4 cards after successful add (after)

### ISSUE-002 — Mobile 375px Horizontal Scroll When Deck Selected

- **Severity:** Medium
- **Category:** Accessibility / Responsive
- **Status:** ✅ **Verified fixed**
- **Commit:** `7fe24ad`

**Description:** At 375px mobile viewport, selecting a deck caused `document.documentElement.scrollWidth` to be 506px (vs 375px viewport). The header contained `min-w-fit` on both the left logo section and right actions section (`index.html:164` and `index.html:188`). When the deck is selected, the header expanded to 506px width, causing horizontal scrollbar to appear.

**Root Cause:** The outer container `<div class="flex flex-col h-screen">` lacked `overflow-x: hidden`. The header's `min-w-fit` elements expand beyond viewport on mobile.

**Fix applied:** Added `overflow-x-hidden` to the outer flex container (`index.html:160`):
```html
<div class="flex flex-col h-screen overflow-x-hidden">
```

**Evidence:**
- Before: `docW: 506, viewW: 375` — horizontal overflow
- After: `docW: 375, viewW: 375` — no overflow ✅

**Screenshots:**
- `screenshots/mobile_scroll_check.png` — Horizontal overflow visible (before)
- `screenshots/mobile_after_fix.png` — No overflow (after)
